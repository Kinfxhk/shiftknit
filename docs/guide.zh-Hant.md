# 排更易使用說明

[English](guide.md)

排更易按你設定的規則自動排更，每份更表在顯示前都經獨立檢查器逐條驗證。所有運算都在你的
瀏覽器內進行，資料不會上載。

> **非法律意見。**「通過檢查」只代表更表符合你自己輸入的規則，並不代表符合任何法例或合約。
> 請參閱[香港休息日預設](hk-rest-day.md)。

## 1. 開啟排更易

- **網上版：**開啟 README 列出的網站。首次瀏覽後可離線使用。
- **在自己電腦執行**（需要 Node.js 22 或以上）：

```sh
npm ci
npm start   # 建立網站並於 http://127.0.0.1:4883/ 提供
```

- **Docker：**見 README。容器只提供靜態網站。

## 2. 設定

1. **項目：**名稱、時區（IANA 名稱，例如 `Asia/Hong_Kong`）、第一日、日數（1–31）、兩更
   之間最少休息時數，以及休息日規則。
2. **技能：**例如 `急救, 持匙人`，最多 8 項。
3. **更份**（最多 6 個）：開始及結束時間（結束時間不遲於開始時間即代表翌日結束，例如
   22:00–07:00）、無薪休息、每個星期幾需要的人數，以及技能要求（例如「最少 1 名急救員」）。
4. **員工**（最多 30 人）：名稱或代號、技能、每週最多及最少工時、最多連續工作日、請假日期、
   希望不用上班的星期幾。可工作時段及其他偏好可在項目檔內設定（見範例）。

按「載入示例」試用小型咖啡店，或開啟 `examples/` 內的檔案：`small-shop.json`、
`care-home-nights.json`（12 小時日更及夜更）、`volunteer-team.json`（倫敦時間，跨越十月
夏令時間結束）。

## 3. 自動排更

按「自動排更」。求解器在背景運行，頁面仍可使用；按「停止」可取消。結果會如實標示：

| 標示                   | 意思                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| **已證明最佳**         | 所有人手需求都已滿足，而且已證明在你的規則下沒有更好的更表。         |
| **可行（未證明最佳）** | 所有需求都已滿足，但搜尋在證明最佳之前已停止。                       |
| **目前最佳（有缺口）** | 部分人手位無法填補。如能證明無法滿足全部需求，會清楚說明並解釋原因。 |
| **無解**               | 沒有更表能同時符合你所有硬性規則（例如兩個互相衝突的鎖定）。         |

顯示的每份更表都已通過獨立檢查器。如求解器產生的更表未能通過檢查，該更表不會顯示，頁面亦會
說明。

### 點解咁排？點解排唔到？

當已證明無法滿足全部人手（或根本無法排更）時，排更易會找出**一小組無法同時滿足的規則**。例如示例咖啡店四名持匙人之中有三人在同一個星期三請假：

- 2026-11-04 的「Opening」需要 1 名具備「keyholder」技能的人員。
- 2026-11-04 的「Closing」需要 1 名具備「keyholder」技能的人員。
- Ada 於 2026-11-04 請假。
- Chloe 於 2026-11-04 請假。
- Fai 於 2026-11-04 請假。

（餘下的持匙人 Dev 無法同時做兩個重疊的更份。）

每個解釋都已在所列期間以窮舉搜尋證明。「最少」代表去掉其中任何一條，衝突就會消失。放寬其中
一條（增加人手、調整技能、減少需求）再試。

### 硬性規則

| 規則       | 檢查方法                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 可工作時段 | 如有設定，整更必須在其中一個時段內。                                                                                 |
| 請假       | 任何更份不可與請假日（當地日曆日）重疊。                                                                             |
| 重疊       | 同一人的更份不可重疊。                                                                                               |
| 休息       | 上一更結束至下一更開始之間的最少時間，跨午夜亦正確計算。                                                             |
| 每週工時   | 以實際工作分鐘（不計休息）計算，夏令時間正確處理。下限只適用於完全在期間內的週。                                     |
| 連續工作日 | 最多連續工作日數（以更份開始日計）。                                                                                 |
| 休息日     | 每 7 日最少 N 個休息日，每個休息日為連續不少於 24 小時不用工作；可選「任何連續 7 日」或「由第一日起每 7 日為一期」。 |
| 人手       | 不會多於需要人數；不足會列為缺口，不會隱藏。                                                                         |
| 鎖定       | 已鎖定的格子保持原有更份（或休息）。                                                                                 |

### 偏好及公平（軟性）

在盡量填滿人手之後，排更易會減低以下分數：員工偏好、工時／週末更／夜更分配差距、與上一期
更表的改動（項目檔），以及工作日之間只休一日。分數連細項顯示，越低越好。

## 4. 手動修改

在「員工 × 日子」表內修改任何格子，同一個檢查器會即時重新檢查，並以紅色標示違反的規則及說明。
按 □ 可**鎖定**格子，再按「自動排更」，其餘格子會圍繞你的選擇重新安排。「週曆」顯示每更由誰
當值。

## 5. 匯出及列印

- **CSV**（員工 × 日子、連工時清單、未填補需求）。任何以 `=`、`+`、`-`、`@`、Tab 或 CR
  開頭的內容都會加上前置撇號，試算表不會把它當作公式執行。
- 每人一個**日曆檔（.ics）**，可匯入手機日曆。時間以 UTC 記錄，跨午夜及夏令時間都準確。
- **項目檔（.json）**用作備份或分享設定；另可匯出**更表（.json）**。
- **列印：**全隊更表、每人一頁，以及列出各員工休息日的**休息日更表**，方便預先張貼。

## 6. 命令列

同一個核心亦可在命令列使用：

```sh
npm run shiftknit -- solve examples/small-shop.json --seed 1 --time-limit 10s --out result.json --text --lang zh-HK
npm run shiftknit -- check examples/small-shop.json result.json --text --lang zh-HK
npm run shiftknit -- export examples/small-shop.json result.json --format ics --staff ada --out ada.ics
```

結束代碼：0 正常；1 輸入錯誤；2 違反規則（check）或有未填補人手位（solve）；3 無法排更；
4 內部檢查失敗。相同項目及 seed 會得到相同結果（除非到達時間上限）。

## 7. 你的資料

項目及更表儲存在此瀏覽器（IndexedDB），顯示設定儲存在 `localStorage`。「刪除此裝置上的所有
資料」會把兩者一併刪除。排更易不會向任何其他網站發出請求。

## 8. v0.1 限制

30 名員工、31 日、6 個更份、8 項技能，每人每日最多一更。不設登入、換更、糧單或通知功能。
